# P4-B 独立集成方案（仅设计，未执行）

## 前置条件

需要人工授权的独立、无GPU训练主机/虚拟机，专用合成MySQL及Redis，不访问生产/共享实例。
先可靠禁用AppConfig.ready的模型预热、真实Agent/工具/Embedding/Ollama；否则禁止启动Django或探针。
固定commit、Python、Django 5.2具体补丁、asgiref、Uvicorn及HTTP协议实现、DB driver、代理版本与配置。
requirements仅>=5.2，不能把参考源码当实际运行版本。禁止用现有可能加载模型的agent/health/作探针。
Redis Analytics继续默认关闭，Session/业务使用专用测试DB；不清理或扫描共享缓存。
只使用有界Fake Agent（可控返回屏障/有限延迟），真实数据库仅合成夹具。
测试工具有限连接/请求/墙钟预算，先串行，需进一步授权后最多小规模2个连接；不在当前训练主机压测。

## 仪表时间线

使用同一服务器单调时钟记录请求进入、响应构造、首次本地handoff、ASGI send、Agent开始/返回、
回放开始/结束、持久化开始/确认、done交接、迭代耗尽、receive断连、close调用/实际清理。
浏览器另记录首事件/done/EOF/错误和UI终态。客户端/服务器时钟不能直接相减而不校准。
request_id用于日志关联，不是用户/Session标签或幂等键；记录不含聊天/画像/凭据。

| 指标 | 定义与注意 |
|---|---|
| TTFT | 客户端首个SSE事件时间，**不是LLM首Token**；与本地intent yield时间分开 |
| SSE连接时长 | HTTP请求至正常EOF/传输中断，按正常/失败/取消分别统计 |
| Agent耗时 | 同步Fake Agent开始到返回；不代表真实模型耗时 |
| 回放耗时 | Agent返回后Trace/chunk阶段，包含原有等待，不混入推理 |
| 持久化耗时 | owned事务开始至commit确认/不确定失败；不能从done推断数据库未出错 |
| 断开检测延迟 | 受控传输断开至服务端可靠receive观察；普通close不当作物理断开证据 |
| 取消后额外资源 | 标记/真实断连后Agent仍运行时间、线程、FD、连接、RSS回落 |
| 活跃连接 | HTTP连接与应用正在执行的同步工作分别计数 |
| 终态计数 | done/error、incomplete、本地cancel、清理失败、提交不确定分别记录 |
| P50/P95/P99 | 直接完整路径采样，按场景分组；不相加阶段P95，披露样本数/低n最大值 |

## 场景矩阵

1. 正常：真实浏览器+代理完整接收卡片/Trace，结果与基线一致，三写一次，done一次。
2. Django ASGI同步适配：在Fake Agent屏障释放前是否实际收到intent；检查整段消费警告与缓冲。
   当前同步代码可能不满足真实逐帧交付；实验用于确认缺口，不偷偷改async或前端弥补。
3. 浏览器Abort、关闭页面、Mock网络RST/中断分别在Agent前/中/后触发；追踪receive→close→检查点。
4. Nginx缓冲开/关、空闲/发送超时、缓慢读者与背压，区分客户端停止读取和服务器可靠断开信号。
5. Trace/chunk中断：保持已交出的内容，不发送取消后的虚假成功；前端EOF提示明确且不重复气泡。
6. 保存前/中/后断开：有界DB屏障/独立代理注入，检查事务完整性、commit确认不确定性及不重复执行。
7. 三写各自失败、commit应答丢失：错误分类、无done、原cause链、没有自动重试；检查实际提交行。
8. done已交给迭代器但客户端未读到：不能将服务器日志当用户收到成功；模拟post-done错误/断流。
9. 多连接：少量有限请求并排验证请求/Session隔离、共享池不被其他close关闭；记录线程/连接释放。
10. 重复HTTP请求：证明request_id不是幂等控制，明确允许产生新执行，不以本轮声称Exactly-Once。

## 验收阈值设计

正确性硬门槛：error之后done=0，持久化失败的成功done=0，自动Agent/DB重试=0，跨用户取消=0，
单次完整业务请求两history/一trace均提交或均回滚；应答丢失单独标未知。
局部取消硬门槛：在下一个已实际到达的协作检查点停止后续生产，不进入未开始的最终事务；
取消与handoff并发以锁内交接的先后定义，不承诺撤回已交出的事件。
无法中断的同步调用不设虚假毫秒停止门槛；分别报其剩余耗时和可观测取消延迟。

独立环境初始诊断门槛（设计值，不是已测SLO）：有界Fake调用/DB屏障释放后5秒内，
本请求持有的generator与测试连接应结束或明确记录cleanup失败；未恢复资源记失败并停止扩大实验。
基线建立后再由人工确定首事件/断连/P95和资源预算；当前没有证据给生产阈值或吞吐承诺。
若目标是可靠实时ASGI取消，则“同步流被预消费/断连未及时传递”属于后续上线阻断，当前只能CONDITIONAL GO。
不能把本地close测试通过改写成此项已通过。

本轮不执行上述实验，不启动服务，不下载/加载模型，也不进入P4-C/P4-D/Go阶段。
